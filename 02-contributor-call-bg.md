## Сътрудничество за ufolens.com

[ufolens.com](https://www.ufolens.com) превръща архива [PURSUE UAP](https://www.war.gov/ufo) на Военния департамент на САЩ в многоезична платформа с възможност за търсене и [публичен API](https://www.ufolens.com/api/v1). Проектът се състои от две половини — локален Python pipeline за поглъщане на данни (`pipeline/`) и edge приложение на TypeScript/Hono (`worker/`) — които се срещат в един интерфейс: публикуван пакет от SQL + активи.

Не са ви нужни никакви облачни идентификационни данни, за да допринесете. Основните модули на pipeline са само със stdlib, а тестовете на Worker се изпълняват срещу хранилище в паметта.

### Настройка

```bash
# pipeline
python3 -m pytest pipeline/tests/          # трябва всички да са зелени, не е нужен pip install

# worker
cd worker && npm install
npm run typecheck && npm test              # tsc --noEmit + vitest
npm run dev                                # localhost:8787
```

### Къде помощта е най-полезна

**i18n / локализация** — `worker/src/i18n/ui-strings.json` е източникът на низове за потребителския интерфейс. Преглед от носител на езика за всяка локализация, различна от английската, е от голяма полза: за откриване на неловки машинни преводи, коригиране на проблеми с RTL/оформлението, подобряване на крайни случаи при договарянето на език.

**Качество на OCR** — по-добра предварителна обработка на стари сканирани документи, писани на пишеща машина, преди OCR; система за оценка, сравняваща енджина с отворен код с резервния Tesseract на примерни страници.

**Достъпност** — одит на рендираните страници (`worker/src/render/`) спрямо WCAG; CSP е стриктен (без `unsafe-inline`), така че решенията трябва да работят в тези рамки.

**Ергономичност на API** — `worker/src/routes/` — пагинация, филтриране, OpenAPI описание, примерни клиенти.

**Устойчивост на Pipeline** — повече пътища за плавна деградация, по-добро отчитане на напредъка, крайни случаи при откриване на разлики (`pipeline/lib/delta.py`).

**Документация** — `docs/20260511/` (繁體中文; `00-*` е индексът). Преводи на проектната документация на английски са добре дошли.

### Основни правила

- Всички пътища са относителни — проектът трябва да е преносим между машини. Без твърдо кодирани абсолютни пътища.
- Не добавяйте pip зависимост към *основен* модул на pipeline. Опционалните етапи могат да използват опционални пакети и трябва да деградират плавно без тях.
- Не отслабвайте машината на състоянията „само напред“ — това е таванът на разходите.
- Не въвеждайте официални отличителни знаци на правителството на САЩ и не добавяйте нищо, което премахва редакции от източника.
- Промени в схемата на D1 засягат **два** файла: `pipeline/lib/manifest_schema.sql` и `db/schema.sql`.
- Тестове с новия код. Съобщения на комитите в стил Conventional-commit.
