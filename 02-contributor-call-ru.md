## Участие в разработке ufolens.com

[ufolens.com](https://www.ufolens.com) превращает [PURSUE UAP архив](https://www.war.gov/ufo) Военного министерства США в многоязычную платформу с возможностью поиска и [публичным API](https://www.ufolens.com/api/v1). Проект состоит из двух частей — локального конвейера импорта Python (`pipeline/`) и edge-приложения TypeScript/Hono (`worker/`) —, которые объединяются в одном интерфейсе: опубликованном бандле SQL и ресурсов.

Для участия в разработке не требуются облачные учетные данные. Основные модули конвейера используют только стандартную библиотеку (stdlib), а тесты Worker'а запускаются с использованием хранилища в оперативной памяти.

### Настройка

```bash
# pipeline
python3 -m pytest pipeline/tests/          # should be all green, no pip install needed

# worker
cd worker && npm install
npm run typecheck && npm test              # tsc --noEmit + vitest
npm run dev                                # localhost:8787
```

### Где помощь будет наиболее полезной

**i18n / локализация** — `worker/src/i18n/ui-strings.json` является источником строк интерфейса. Проверка любой локали, отличной от английской, носителем языка будет очень ценна: это поможет исправить некорректный машинный перевод, устранить ошибки RTL/разметки issues и улучшить обработку граничных случаев согласования языка.

**Качество OCR** — улучшение предобработки старых сканов печатных машинок перед OCR; создание среды оценки для сравнения open-source движка с резервным вариантом Tesseract на тестовых страницах.

**Доступность (Accessibility)** — аудит отрендеренных страниц (`worker/src/render/`) на соответствие WCAG; CSP очень строгий (без `unsafe-inline`), поэтому решения должны работать в этих рамках.

**Эргономика API** — `worker/src/routes/` — пагинация, фильтрация, описание OpenAPI, примеры клиентов.

**Надежность конвейера** — более плавные механизмы деградации функциональности, улучшенная отчетность о прогрессе, обработка граничных случаев обнаружения изменений (`pipeline/lib/delta.py`).

**Документация** — `docs/20260511/` (繁體中文; `00-*` — индекс). Приветствуются переводы проектной документации на английский язык.

### Основные правила

- Все пути, относительные — проекта, должны быть переносимыми между разными машинами. Никаких жестко закодированных абсолютных путей.
- Не добавляйте pip-зависимости в основные (*core*) модули конвейера. Опциональные этапы могут использовать опциональные пакеты, но должны корректно работать и при их отсутствии.
- Не ослабляйте конечный автомат, работающий только вперед —, так как это определяет потолок затрат.
- Не используйте официальную символику правительства США и не добавляйте ничего, что могло бы отменить редактирование (redactions) исходных данных.
- Изменения схемы D1 затрагивают **два** файла: `pipeline/lib/manifest_schema.sql` и `db/schema.sql`.
- Тесты для нового кода. Сообщения коммитов в формате Conventional Commits.

Сначала ознакомьтесь с `CLAUDE.md` и `docs/20260511/00-*`, затем создайте issue, чтобы обсудить любые структурные изменения перед PR.
